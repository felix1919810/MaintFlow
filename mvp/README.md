# MaintFlow 点检交接 MVP 0.2

这是2026-11-26新增的场景实现，代码位于mvp目录，原src目录中的平台参考演示保持不变。

## 运行

需要Node.js 22或以上，无依赖，无需npm install。在仓库根目录执行：

```powershell
node mvp/server.mjs
```

打开 <http://127.0.0.1:4181>。Ctrl+C停止。不要直接双击HTML，浏览器需通过本机HTTP加载模块。端口占用可在PowerShell先设置 `$env:PORT=4182`。

## 5分钟演示路径

1. 操作者选林亦舟；业务号填CHK-001，设备M-01，描述填“运转杂音”，来源选MANUAL-M01-v1。保存后保留原始描述并标准化为“设备异响”，状态待交接。
2. 切换唐映秋，选中CHK-001；指定林亦舟接手，填写交接说明及未解项，提交后为待接手。
3. 仍用唐映秋尝试接手会被拒绝；切回林亦舟确认接手后才变为处理中，并新增责任转移审计。
4. 填设备修好时间、稳定复产时间、现场授权确认人及处理结论，勾选已完成现场安全确认，记录闭环。时间须满足创建≤修好≤稳定复产≤当前时间。
5. 刷新仍保留本浏览器任务；可按状态筛选，导出完整JSON（来源快照、交接、闭环与审计）。
6. 新建CHK-002不选来源，或选冲突来源/勾漂移，均进待核对。由计划员、安全岗或经理选有效同设备来源并填写人工依据后才允许交接。

来源时间超过15分钟后不可直接通过或交接；需要现场重新核实。演示中可先导出，再通过“重置合成数据”重开一轮，刷新合成来源。重置会删除本浏览器当前MVP记录，界面有确认提示。

## 已实现

- 原始描述与统一术语并存，唯一业务号阻止重复创建。
- 来源ID、版本、摘录、设备与时间快照；缺资料、版本冲突、设备不符、过期及漂移转人工。
- 点检→核对→交接→指定人接手→人工闭环状态机；退回需原因；每次动作审计。
- 修好与稳定复产两时标、现场确认人独立记录。
- 浏览器localStorage持久化、筛选、JSON导出、显式重置；存储读取/写入错误不冒充成功。

## 边界

演示身份下拉不是服务端鉴权。所有样本合成，本地单用户存储不是多人共享数据库，不应填真实工厂敏感资料。无云API/LLM/真实设备连接，无自动维修/控制/解除联锁/批准复产。闭环登记只是记录人提供的结果，不执行或认证安全动作。后续生产版需账号权限、后端数据与并发控制、真实授权来源及现场验收。
